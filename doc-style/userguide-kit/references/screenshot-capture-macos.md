# เก็บภาพหน้าจอสำหรับ User Guide บน macOS

เอกสารนี้สำหรับคนที่ต้องเก็บภาพหน้าจอระบบจริงไปใส่ User Guide อ่านแล้วเก็บภาพได้ครบชุด
โดยไม่ติดข้อมูลส่วนตัวและไม่ต้องลองผิดลองถูกใหม่ทุกครั้ง

ใช้คู่กับ [thai-userguide-style.md](../../thai-userguide-style.md) ซึ่งคุมเรื่องคำ
ไฟล์นี้คุมเรื่อง **การได้ไฟล์ภาพมา**

ที่มา: ถอดจากงานเก็บภาพระบบ NetSuite บน sandbox จริงผ่าน Chrome (2026-08-20)
ระหว่างทางจับภาพผิดไป 3 ครั้งจนติดหน้าต่างส่วนตัว จึงสรุปเป็นกฎกลาง

---

## 1. ข้อเท็จจริงที่ต้องรู้ก่อน

| ข้อเท็จจริง | ผลที่ตามมา |
|---|---|
| เครื่องมือ browser (MCP) คืนภาพเข้าบทสนทนา แต่ไม่เขียนไฟล์ลงดิสก์ที่เข้าถึงได้ | ต้องเก็บภาพด้วย `screencapture` ของ macOS แยกอีกทาง |
| `screencapture -R` ใช้ **พิกัดรวมทั้งเดสก์ท็อป** ไม่ใช่พิกัดต่อจอ | `-D 2 -R 0,0,...` จะไปจับจอแรก ไม่ใช่จอสอง |
| `screencapture -D <n>` จับได้เฉพาะจอนั้นทั้งจอ แต่รวมแถบเมนูและแถบ tab | ได้ภาพสะอาดแต่ต้องครอบตัดส่วนบนทิ้ง |
| หน้าต่างที่แย่งโฟกัสจะติดมาในเฟรมทันที | การ `activate` แอปก่อนจับภาพ **ไม่รับประกัน** ว่าจะได้หน้าต่างที่ต้องการ |
| เครื่องที่ไม่มี `PIL` และไม่มี `Quartz` | ครอบตัดหลังจับภาพไม่ได้ ต้องกำหนดกรอบให้ถูกตั้งแต่ตอนจับ |

## 2. วิธีที่ใช้ได้จริง

**หลักการ: ให้ระบบที่จะถ่ายอยู่คนละจอกับหน้าต่างงานของตัวเอง แล้วจับด้วยพิกัดตายตัว**

1. ย้ายหน้าต่างเบราว์เซอร์ที่จะถ่ายไปจออีกตัว เปิดเต็มจอ
2. หา offset ของจอนั้นในพิกัดรวม โดยจับทั้งจอหนึ่งครั้งแล้วดูว่าเนื้อหาเริ่มที่ x เท่าไร

   ```bash
   screencapture -x -D 2 /tmp/probe.png
   ```

   จอที่วางอยู่ขวาของจอหลักกว้าง 1440 จะมี offset x = 1440

3. จับด้วยกรอบตายตัว ไม่ต้อง activate ไม่ต้อง sleep รอโฟกัส

   ```bash
   screencapture -x -R 1440,166,1920,850 shots/01-หน้าค้นหา.png
   ```

   `1440` = offset x ของจอ · `166` = ตัดแถบเมนู แถบ tab และ banner ทิ้ง ·
   `1920,850` = กว้าง x สูง ของพื้นที่เนื้อหา

4. **เปิดดูทุกภาพก่อนนำไปใช้** ภาพที่ผิดให้ลบทันทีก่อนทำงานต่อ

## 3. ค่า offset ด้านบนที่ต้องตัดทิ้ง

วัดจาก Chrome บน macOS ที่เปิดเต็มจอ

| ตัดถึง y | ได้อะไร |
|---|---|
| 132 | ตัดแถบเมนูและแถบ tab ทิ้ง เห็น header ของระบบครบ |
| 166 | ตัด banner ของ automation ทิ้งด้วย เสียส่วนบนของ header ไปเล็กน้อย |

ถ้าขับเบราว์เซอร์ด้วยเครื่องมือ automation จะมี banner แจ้งว่ากำลัง debug อยู่ด้านบน
banner นี้โผล่ทุกครั้งที่มีคำสั่งใหม่และหายเองในไม่กี่วินาที **ใช้ค่า 166 ไว้ตลอดปลอดภัยกว่า**
เพราะ banner โผล่หรือไม่โผล่ไม่ทำให้กรอบเลื่อน

## 4. ตั้งสภาพหน้าจอด้วย URL ไม่ใช่การคลิก

หน้าที่รับค่าผ่าน query string ให้ยิง URL ตรงเพื่อตั้งสภาพที่ต้องการ เร็วกว่าและทำซ้ำได้เหมือนกันทุกครั้ง

```
...?stepfield=find&dosearch=T&filter_threshold=1.00&filter_onlynojv=T
```

เหลือใช้การคลิกเฉพาะสิ่งที่ทำด้วย URL ไม่ได้ เช่น การกางแถวในตาราง

> ข้อควรระวัง: ห้ามยิง URL ที่เป็นการ submit จริงเพื่อเอาภาพ ถ้าหน้านั้นสร้างเอกสาร
> ต้องขออนุญาตเจ้าของระบบก่อน และใช้กับ record ที่เจ้าของระบบระบุมาให้ใช้ทดสอบเท่านั้น

## 5. ความเป็นส่วนตัว

การจับภาพระดับจอเห็นทุกอย่างที่อยู่บนจอนั้น กฎ 3 ข้อ

1. เลือกกรอบให้แคบที่สุดเท่าที่เนื้อหาต้องการ อย่าจับทั้งเดสก์ท็อปแล้วค่อยมาตัด
2. เปิดดูทุกภาพก่อนใช้ ถ้าติดหน้าต่างอื่นให้ **ลบทันที** ไม่เก็บไว้ "เผื่อใช้"
3. แถบ tab ของเบราว์เซอร์มีชื่อหน้าที่เปิดอยู่ ซึ่งมักมีชื่อไฟล์หรือชื่อสคริปต์ภายใน
   ต้องตัดออกทุกครั้งตามข้อ 9 ของ [thai-userguide-style.md](../../thai-userguide-style.md)

## 6. ตั้งชื่อไฟล์ภาพ

เรียงตามลำดับที่ปรากฏในเล่ม แล้วตามด้วยสิ่งที่อยู่ในภาพ

```
shots/01-หน้าค้นหา.png
shots/02-กางรายละเอียด.png
shots/03-หน้ายืนยันและ-preview.png
shots/04-หน้าติดตามสถานะ.png
```

`build_userguide.py` จะใส่คำว่า "ภาพที่ n" ให้อัตโนมัติจากลำดับที่อ้างในไฟล์ .md
ชื่อไฟล์จึงมีหน้าที่ให้คนหาไฟล์เจอเท่านั้น ไม่ได้ไปโผล่ในเล่ม

## 7. เมื่อวิธีนี้ใช้ไม่ได้

| อาการ | ทำอะไร |
|---|---|
| มีจอเดียว | ให้เจ้าของเครื่องเก็บภาพเองด้วย `Cmd+Shift+4` หรือเครื่องมือ annotate แล้วส่งไฟล์มา |
| ระบบต้อง login และ session อยู่บนเบราว์เซอร์ของผู้ใช้ | ต้องใช้เบราว์เซอร์ตัวนั้น ห้ามพา session ไปที่อื่น |
| ต้องการกรอบไฮไลต์สีในภาพ | เก็บภาพดิบก่อน แล้วให้ skill `agent-browser-qa` หรือเครื่องมือ annotate ใส่กรอบ (แดง = จุดคลิก · เขียว = จุดสังเกต) |
